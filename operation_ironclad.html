Analyst. I'll keep this brief. At 0300 this morning, automated sensors on the USS Meridian flagged unusual activity on the shipboard command network. Someone — or something — got in. We don't know what they touched or what they left behind.

Your job is to go through this system like you own it. Check every user account. Sniff the traffic. Dig through the logs. Harden whatever's been left open.

We have one hour before this ship has to be operationally ready. Any vulnerability you don't find — the adversary might. Don't leave anything on the table.
Your Role
You are a Cyber Warfare Technician (CWT) assigned to NIWC Pacific's rapid response team. The USS Meridian is a fictional training vessel. The Linux system you'll be working inside is the ship's simulated command server. Every vulnerability is real — every fix you apply matters.
What You'll Learn

  • Network traffic analysis using Scapy and Wireshark
  • Digital forensics: reading system logs, finding attacker traces

OP-01
👤
Ghost in the Roster
⏱ 10–15 min
Unknown accounts have appeared on the ship's command server. Identify and eliminate unauthorized access before someone uses it.
User Management Sudo Audit Permissions Privilege Escalation
Mission Briefing
Our system administrator flagged three accounts that don't appear in the authorized personnel manifest. One of them has sudo privileges — meaning they could do real damage. Another has a world-writable home directory. Investigate all user accounts on the system and restore proper access control.
Objectives
  • List all user accounts on the system and cross-reference against the authorized list
  • Identify which accounts do not belong and remove them
  • Audit the sudo group — who has it that shouldn't?
  • Find the file with dangerous permissions and correct it
  • Check for accounts with empty passwords
Authorized Crew
The following accounts are the only valid users: admin, wells, reyes, nakamura. Any others should be treated as unauthorized.
Tools
cat /etc/passwd groups [user] sudo deluser sudo visudo find / -perm 777 passwd -S [user]
Hint: The /etc/sudoers file and the sudo group both grant elevated privileges. Check both. Also look carefully at /etc/passwd for accounts with UID 0 other than root.
OP-02
📡
Dark Signal
⏱ 15–20 min
Unusual traffic is leaving the ship network. Analyze the packets, identify the threat, and trace what data may have been exfiltrated.
Scapy Wireshark Packet Analysis Data Exfil Detection
Mission Briefing
Network sensors picked up high-volume outbound traffic at 0247 hours. A packet capture file has been saved to your desktop: meridian_traffic.pcap. A Python script using Scapy is pre-installed to help you analyze it. Find the suspicious connection, identify the destination IP and port, and determine what protocol was used to hide the data.
Objectives
  • Open the PCAP file in Wireshark and examine the traffic visually
  • Run the provided Scapy analysis script to enumerate packet types
  • Identify a suspicious DNS query containing encoded data (DNS tunneling)
  • Decode the message hidden in the DNS requests using base64
  • Identify the source process that generated the traffic (bonus)
Scapy Walkthrough
meridian_analyst.pyPYTHON 3 — SCAPY 2.5
from scapy.all import rdpcap, DNS, DNSQR
# Load the capture file
packets = rdpcap("meridian_traffic.pcap")
# Filter for DNS queries only
dns_pkts = [p for p in packets if p.haslayer(DNS)]
for pkt in dns_pkts:
    if pkt.haslayer(DNSQR):
        print(pkt[DNSQR].qname)
# What do you see in the subdomains?
Hint: DNS tunneling hides data inside DNS query subdomains. Look for queries to domains like aGVsbG8=.exfil.badsite.net. That subdomain might be base64. Try echo "aGVsbG8=" | base64 -d.
OP-03
🔍
Buried Evidence
⏱ 10–15 min
The attacker tried to cover their tracks. Dig through system logs and hidden files to reconstruct what they did — and find what they left behind.
Log Analysis File Forensics Hidden Files Cron/Backdoors
Mission Briefing
Forensic indicators suggest the attacker accessed the system approximately 18 hours ago. They deleted some files and attempted to clear bash history. But logs remember more than people think. Find the attacker's entry point, the files they accessed, and any persistence mechanisms they left behind.
Objectives
  • Check /var/log/auth.log for failed and successful login attempts
  • Find a hidden file in a user's home directory containing stolen data
  • Examine /var/spool/cron and crontab -l for malicious scheduled tasks
  • Identify a SUID binary that shouldn't have the SUID bit set
  • Recover the deleted bash history from /tmp (attacker forgot to clean it)
Key Log Locations
/var/log/auth.log /var/log/syslog /home/*/.*history /tmp/ crontab -l find / -perm -4000
Hint: Files starting with . are hidden. Use ls -la to see them. SUID binaries run with the file owner's privileges — if /usr/local/bin/something has the SUID bit, that's suspicious.
OP-04
🛡️
Lock It Down
⏱ 10–15 min
Neutralize every remaining vulnerability before the USS Meridian goes operational. Harden the firewall, kill unnecessary services, and patch the OS.
UFW / iptables systemd Service Audit Open Ports
Mission Briefing
You've found the attacker. Now make sure they — or anyone else — can't get back in. Enable the firewall, close ports that shouldn't be open, disable unnecessary services, and apply any outstanding security updates. Complete the hardening checklist before departure.
Hardening Checklist
  • Enable UFW and set default deny-incoming / allow-outgoing policy
  • Allow only SSH (port 22) and HTTP (port 80) through the firewall
  • Disable and stop the telnetd service (plain-text protocol — unacceptable)
  • Disable and stop the vsftpd FTP service
  • Run apt update && apt upgrade to apply security patches
  • Verify no unnecessary ports are listening with ss -tlnp
Firewall Commands
ufw_setup.shBASH
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow ssh
sudo ufw allow 80/tcp
sudo ufw enable
sudo ufw status verbose
Status: active
Hint: systemctl list-units --type=service --state=running shows every active service. Think critically: does a shipboard command server really need FTP? Telnet sends passwords in plain text. Never allow it.

VM Setup
Guide
Before you start, you need to boot into the mission environment. Download the VM image, import it into VirtualBox or VMware, and boot it up. Once you see the login prompt for the USS Meridian Command Terminal, you're ready. Credentials on your mission card.
1

Download VirtualBox

Install VirtualBox (free) from virtualbox.org. It runs on Windows, macOS, and Linux. VMware Workstation Player also works.

2

Import the VM Image

Open VirtualBox → File → Import Appliance → Select the .ova file. Keep the default settings. The VM is pre-configured with 2GB RAM and 2 CPU cores.

3

Boot and Log In

Start the VM. At the login prompt, enter: Username: analyst / Password: ironclad2024. You'll land in the home directory with your mission files.

4

Run the Scoring Engine

Open a terminal and run sudo ./score.sh at any time to check your progress. It will tell you which objectives are complete and your current point total.

5

Take a Snapshot First

In VirtualBox: Machine → Take Snapshot, named "Clean Start." If you break something, you can restore to this point without re-importing.

Heads up: The VM is intentionally insecure. Do not connect it to your host network or the internet beyond NAT. Keep it isolated in "NAT" or "Host-Only" network mode in VirtualBox settings.

Points are awarded automatically by the scoring engine each time you run sudo ./score.sh in the VM. The engine checks whether each vulnerability has been fixed — like a live CyberPatriot score panel.
